# Карта кода

Что лежит в каждом файле `app/`. Общая схема и технологии — `PROJECT_CONTEXT.md`, раздел 5; куда класть новый код — `docs/coding-standards.md`, правило 7. Обновлять вместе с кодом.

| Файл | Назначение |
|---|---|
| `app/bot/main.py` | Сборка бота (`build_dispatcher`: белый список → отчёты об ошибках → обработчики трекера; при запуске `set_my_commands`), ядра с источниками и планировщика (`add_jobs`: опрос и отправка очереди раз в минуту, проверка копии базы раз в час, первый раз сразу при запуске) |
| `app/bot/access.py` | `AccessMiddleware`: белый список для всех апдейтов, fail-closed |
| `app/bot/error_handler.py` | Отчёты владельцу об ошибках (`ErrorMiddleware`), сохранение в `data/temp_failure.txt` |
| `app/config.py` | `Settings` из окружения, разбор `ALLOWED_TELEGRAM_USER_IDS`, `Settings.owner_chat` (единственный способ узнать чат владельца), `time_zone_of` (пояс из `BOT_TIMEZONE`, без него UTC и предупреждение) |
| `app/providers/` | `tmdb.py`, `anilist.py`, `shikimori.py`: клиенты внешних API с ограничением частоты, на них стоят источники ядра; `igdb.py`, `steam.py` — для куска 6, пока не подключены. Для аниме v2: `ShikimoriClient.fetch_entries` (записи с их связями; сбой — `ShikimoriError`), `search_anime(strict=True)`, `AniListProvider.get_anilist_ids` (MAL-id → AniList-id одним запросом на 50 id), `AniListProvider.get_schedules` (статус, число серий и ближайшая серия по id AniList, 50 id на запрос; сбой — исключение, а не пустой список) |
| `app/tracker/core.py` | Фасад `Tracker` — единственная дверь в ядро (бот и веб видят только его): часы, отправитель и источники передаются снаружи; создаёт модули ниже и передаёт им вызовы, без SQL и правил; каждый публичный метод, читающий или пишущий базу, — `async` (правило 1 в `docs/coding-standards.md`). Пере-экспортирует ошибки, результаты и `TestSample` |
| `app/tracker/context.py` | Общий контекст ядра `CoreContext`: фабрика сессий, `write_session()` (сессия, чья транзакция сразу открыта на запись; через неё пишет всё ядро), часы, отправитель, `default_tz` (не меняется), блокировки опроса и доставки; `Sender`, `Clock`, `naive_utc` |
| `app/tracker/errors.py`, `results.py` | Ошибки ядра (`TitleNotFound`, `UnknownTitle`, `UnknownEvent`, `UnknownKind`, `UnknownSeason`) и результаты (`AddResult`, `WatchedResult`, `DeleteResult`, `TitleSummary`, `WatchableSeason`, `SummaryResult`, `TestEventResult`, `DeliveryReport`, `PollReport`). Без базы |
| `app/tracker/settings_store.py` | `SettingsStore`: порог частей (`part_gap_weeks`), правила доставки (`delivery_rules`, `set_delivery_rules`), часовой пояс (настройка или `default_tz`, читается там, где нужен) |
| `app/tracker/titles.py` | `Titles`: поиск и добавление (первые сезоны и время первой проверки спрашивает у объекта опроса типа), удаление, «Посмотрел», «Следить», отметки сезонов, список, карточка |
| `app/tracker/storage.py` | Что делят части ядра в одной сессии: сезоны и серии (`store_seasons`, `load_seasons`, `sync_seasons`), сохранённые снимки (`own_state`, `stored_snapshot`), пересчёт статуса (`refresh_status`) |
| `app/tracker/polling.py` | `Polling.poll_due` (проход, изоляция ошибок, отложенная проверка) и `Pollers`; единственная таблица `POLLER_CLASSES` (`TitleKind` → объект опроса), `POLLED_STATUSES` |
| `app/tracker/pollers/` | Объект опроса на тип с одинаковыми действиями (`base.Poller`: `first_seasons`, `first_check`, `store_extras`, `apply`): `movie.py`, `series.py`, `anime.py` (в том числе записи частей и фильмов франшизы), `sequels.py` (архивный фильм, продолжения коллекции) |
| `app/tracker/queue.py` | `EventQueue`: `record_event` / `record`, постановка события в очередь (`enqueue`), `queued_since` (есть ли событие с таким ключом после момента), сообщения о сбое (`queue_failure_notices`: событие тайтла и время его последнего сообщения пишутся одной транзакцией) |
| `app/tracker/delivery_service.py` | `DeliveryService`: `deliver_pending`, `summary_now`, чтение очереди, отправка, учёт попыток, кнопки сводки (`MAX_SUMMARY_BUTTONS`) |
| `app/tracker/test_samples.py` | `TestSamples`: образцы «Тестового события» (`TestSample`), `send_test_event`, проверка правил доставки (`DeliveryCheck`, `DELIVERY_CHECKS`, `delivery_check_by_id`, `delivery_check_moment`) |
| `app/tracker/models.py`, `db.py`, `migrations/` | `models.py` (в том числе `seasons`, `episodes`, `season_parts`, `franchise_movies` и `settings`; порог частей — `part_gap_weeks()` / `set_part_gap_weeks()`), `db.py` (SQLite в режиме WAL; начало транзакции пишет сам движок: `BEGIN`, а для соединения с параметром `WRITE_OPTION` — `BEGIN IMMEDIATE`; в базе в памяти все транзакции идут по очереди через один замок, потому что соединение одно; миграции), `migrations/` (отдельный Alembic, `alembic_tracker.ini`) |
| `app/tracker/dedup.py` | Общие части ключей дедупликации (`moved_key` — ключ переноса даты: прежний ключ и момент предыдущего взгляда). Без базы и сети |
| `app/tracker/movie_events.py` | События фильма: `detect_events` (сравнение двух снимков; ключ переноса содержит новую дату и момент предыдущего взгляда), тексты сообщений, `check_interval` (когда проверять снова), образцы для «Тестового события». Без базы и сети |
| `app/tracker/kinds.py` | Одна таблица свойств типа: `KINDS[TitleKind]` → `KindInfo` (подпись, значок, просьба ввести название, имя источника, «сезонный», «время серии на часах владельца»), `is_seasonal`, `seasonal_kinds`. Перечисления `TitleKind`, `TitleStatus`, `DeliveryStatus` лежат в `models.py`. Без базы и сети |
| `app/tracker/cards.py` | Текстовая карточка тайтла (`TitleCard`, `format_card`): названия, год, жанры, даты, «не объявлена»; у сериала вместо дат строки сезонов («Сезон 2: вышло 5 из 8, следующая — пн, 12 окт», анонс, просмотренные) |
| `app/tracker/sequel_events.py` | Продолжения архивного фильма: `Sequels` (состояние коллекции), `detect_sequel_events`, текст сообщения, интервал проверки (неделя), образец для «Тестового события». Без базы и сети |
| `app/tracker/actions.py` | Кнопки под сообщением и карточкой: `Action`, `event_actions` («Посмотрел» под событиями фильма, «Следить» под продолжением, «Карточка» под любым событием с тайтлом, кроме продолжения), `card_actions` («Удалить» — в карточке любого тайтла, `DELETE`). «📺 Просмотренные сезоны» в карточке сериала (`SEASONS`). Бот превращает их в кнопки Telegram (`tact:<имя>:<число>`) |
| `app/tracker/sources/tmdb_sequels.py` | Адаптер TMDb для продолжений: фильм → его коллекция (`/collection/{id}`) → `SequelSnapshot`. Источник `tmdb_sequels`; коллекция спрашивается при каждой проверке, потому что фильм может попасть в неё позже |
| `app/tracker/seasons.py` | Сезоны сериала и аниме: `Season`, `Episode`, `Part` (часть сезона: `Season.parts(gap)` режет сезон по разрыву больше порога; у сезона аниме части заданы (`Season.cuts`, `PartCut`: первая серия и число серий части) и разрыв не применяется), статус по часам (анонсирован / идёт / вышел; в базе не хранится), `summarize` — текущий сезон или его текущая часть, анонс, просмотренные. Без базы и сети |
| `app/tracker/sources/tmdb_series.py` | Адаптер TMDb для сериалов: `parse_search`, `parse_show` (чистый разбор `/tv/{id}` и `/tv/{id}/season/{n}`, в том числе `status` шоу), `TmdbSeriesSource` (подсказки и снимок; сезоны пачками по 20 в одном запросе `append_to_response`). Источник `tmdb_tv`; в строке снимка хранится только `show_status` |
| `app/tracker/progress.py` | Автостатус сериала и аниме: `series_status` по отметкам сезонов и признаку «закрыт» → «Хочу» / «В процессе» / «Жду» / «Досмотреть» / «Просмотрено» + включено ли слежение. Без базы и сети. Применяется в ядре (`storage.refresh_status`) при отметке сезона, добавлении и опросе |
| `app/tracker/series_events.py` | События сериала: `ShowState` (сезоны + статус шоу, `keeping_known` — пробелы в ответе источника не затирают известное), `detect_events` (сравнение двух проверок по `observed_at` и `now`), тексты сообщений (у разделённого сезона — про часть), `check_interval`, образцы для «Тестового события». Ключ дедупликации: `series:<тайтл>:s<сезон>[:p<часть>][:e<серия>]:<тип>` (часть — только у сезона с разрывом), у переноса — ещё новая дата, у закрытия — статус и последний сезон. Без базы и сети |
| `app/tracker/sources/shikimori_anime.py` | Адаптер Shikimori для аниме: `parse_search` (одна подсказка на франшизу), `collect_entries` (обход цепочки `prequel`/`sequel` пачками по 50 id), `chain_order`, `group_seasons`, `build_snapshot` (сезоны, части, фильмы), `assign_anilist_ids`, `ShikimoriAnimeSource` (подсказки и снимок). Источник `shikimori`; первичный id тайтла — id первого сезона, ключ франшизы лежит в состоянии снимка (не в `external_ids`: один ключ делят несвязанные цепочки). Даты уже вышедших серий Shikimori не знает: им ставится день старта записи, следующей — её момент; точное расписание — AniList: `snapshot()` кладёт в снимок `schedules` (по Shikimori-id части; только части, которые Shikimori не считает вышедшими целиком; сбой AniList даёт снимок без них). Без базы и сети |
| `app/tracker/sources/anilist_schedule.py` | Адаптер AniList для аниме: `parse_schedules` (сохранённый ответ → `PartSchedule` по id AniList: статус, сколько серий вышло, номер и момент ближайшей). «Вышло» = номер ближайшей − 1, у законченной записи — все серии; если AniList не говорит ни того ни другого, `released` = None («расписания нет», а не «ничего не вышло»). Без базы и сети |
| `app/tracker/delivery.py` | Правила доставки: `DeliveryRules` (часовой пояс, рабочие дни, час сводки, тихие часы; `check` — час сводки не внутри тихих часов; `holds` — бот молчит ли сейчас, `release` — когда может уйти событие, поставленное в очередь в такой-то момент, `next_silence` — ближайшее начало молчания после момента, `due` — что уходит сейчас по одному и что сводкой), `fold` (складывание: сбои одного источника и причины — везде, серии — только в сводке), `summary_messages` (текст сводки, деление по длине). Проверка правил доставки (`DeliveryCheck`, `DELIVERY_CHECKS`) живёт в `test_samples.py`. Без базы и сети |
| `app/tracker/failures.py` | Сообщения о сбое источника: `reason_of` (исключение → причина: таймаут, нет соединения, 429, ключ, 5xx, «тайтла больше нет», неизвестная), `message_one` / `message_many(источник, причина, названия)` (тексты, склонение «тайтл/тайтла/тайтлов»), `failure_payload` и `foldable` (что кладётся в событие и какие события можно сложить), `source_name` (ключ источника → TMDb / Shikimori), `TitleGone`, `COOLDOWN` (24 часа), образцы для «Тестового события». Очередь и учёт «когда сообщали» — в `queue.py` (`queue_failure_notices`: событие тайтла и время его последнего сообщения пишутся одной транзакцией). Без базы и сети |
| `app/tracker/anime_events.py` | События аниме: `relayout` (перекладывает сохранённые сезоны в нумерацию нового ответа по записям Shikimori: тикет 31), `assemble` (сводит сезоны Shikimori и расписание AniList: для части с расписанием берёт серии из AniList, для части, о которой AniList промолчал, оставляет сохранённое, для остальных верит Shikimori; дата вышедшей серии не меняется, найденная только что получает момент проверки, кроме серии записи, которой у тайтла не было и которая вышла до прошлой проверки, — её день остаётся), `flavor` (иконка 🎌, префикс ключей `anime:`, часовой пояс владельца), `detect_movie_events` (фильм франшизы анонсирован / вышел), образцы для «Тестового события». Сезонные события — те же `series_events.detect_events`. Без базы и сети |
| `app/tracker/sources/dates.py` | Разбор даты из текста в двух местах: `parse_response_date` / `response_year` — мягкий, для ответа внешнего сервиса (мусор — «даты нет»); `parse_date` — строгий, для сохранённого нами (мусор — `ValueError`). Адаптеры TMDb и Shikimori, `movie_events`, `sequel_events` и `titles` берут их, своих копий нет. Без базы и сети |
| `app/tracker/sources/tmdb_movies.py` | Адаптер TMDb для фильмов: `parse_search`, `parse_movie` (чистый разбор ответа), `TmdbMovieSource` (подсказки и снимок). Источник `tmdb_movie` |
| `app/bot/tracker_handlers.py` | Бот ↔ ядро: все обработчики на одном `Router` с фильтром владельца (`register_tracker_handlers`), «Тестовое событие» (в списке последний пункт «Проверить правила доставки», `tchk:open` → `twin:<сценарий>`), «Сводка сейчас» (кнопка и `/summary`), `/start` и меню из четырёх кнопок, `BOT_COMMANDS` для `set_my_commands`, «Добавить», «Мои тайтлы», кнопки «Посмотрел» / «Следить» / «Карточка» / «Удалить» (вопрос `tdel:y|n:<тайтл>`), удаление пачкой `tdm:` (выбор в памяти бота: `selections`) и выбор просмотренных сезонов `tsea:<тайтл>:<сезон>` (фильтр владельца стоит на роутере), `TelegramSender` (с кнопками под сообщением) |
| `app/utils/` | `logging_config.py` (`MaskingFormatter`), `secrets_mask.py`, `backup.py` (копия базы средствами SQLite по пути из `tracker/db.py: database_file`, асинхронная задача планировщика `backup_database`, копирование в потоке) |
