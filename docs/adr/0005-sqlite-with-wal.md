# Остаёмся на SQLite в режиме WAL

Для одного владельца SQLite достаточно, а резервная копия — один файл, что важно для бэкапов и для простой установки шаблона. Режим WAL нужен, чтобы веб-приложение и фоновый опрос не блокировали друг друга. PostgreSQL отвергнут: он оправдан только при множестве одновременных пользователей, а в этой архитектуре его нет (см. ADR 0001).

## Consequences

- Смена базы позже дорога: схема, миграции и бэкапы привязаны к SQLite.
- Резервная копия делается средствами SQLite (online backup), а не простым копированием файла работающей базы.
