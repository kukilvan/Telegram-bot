## 1. Цель

Личный трекер релизов фильмов, сериалов, аниме и игр для одного владельца. Бот сообщает о важных событиях (объявлена дата, вышла серия, игра вышла на моей платформе, скидка), хранит прогресс и оценки владельца. Основной интерфейс будущего продукта — веб-приложение (ADR 0002), Telegram-бот остаётся каналом доставки. Позже код выкладывается на GitHub как шаблон «сделай себе такого же» (новый репозиторий с чистой историей).

Что решено убрать (убрано в тикете 12; подробности в обсуждении перед ADR): заметки и теги, команды `/add`, `/remove`, `/watchlist`, `/note`, `/notes`, `/events`, `/search`, `/searchgame`, inline-поиск, подтверждение «уже вышел, добавлять?», события «Русская озвучка» и «KinoPub», источник RAWG и неофициальный запрос PSN, все хардкоды под владельца.

Запуск (PowerShell, Windows). Бот может работать только в одном экземпляре.

Остановить бота:
```powershell
.\stop-bot.ps1
```
Запустить бота:
```powershell
cd E:\LocalAI\Bionic\Telegram-bot
.\start-bot.ps1
```
(скрипт сам переходит в свою папку, поэтому работает и из другой, например `C:\` с полным путём к нему; проверяет, что Docker Desktop установлен и запущен и что есть `.env`; **не пускает `.env` со знаком `$`** — называет номер строки и имя настройки (значение не выводит); сам останавливает старого бота из `.venv` (только процессы с целой командой `-m app.main` / `-m app.bot.main`); `docker compose up -d --build` собирает образ и поднимает контейнер — бот, опрос и веб одним процессом (ADR 0007), ход сборки виден по ходу; затем **до 90 секунд ждёт итога** (контейнер `healthy`): «Готово. Бот работает в Docker. Приложение: http://localhost:<порт>», либо «Запуск не удался» с 30 последними строками журнала, либо «запускается дольше обычного»; если токен бота неверного вида — добавляет строку «Внимание: бот не подключён к Telegram…» (веб при этом работает); порт занят — подсказывает `WEB_PORT=8081` в `.env`. Окно можно закрывать: бот работает в Docker и поднимается сам вместе с Docker Desktop.) Остановить: `.\stop-bot.ps1`. Журнал: `.\logs-bot.ps1` (выход — `Ctrl+C`, бот продолжает работать). Другого способа запуска нет: `python -m app.bot.main` только подсказывает `.\start-bot.ps1`. Веб открыт только для этого ПК (порт опубликован на `127.0.0.1`): `http://localhost:8080/health` (`{"status":"ok"}`) отвечает без входа, остальное — после входа по паролю `WEB_PASSWORD` из `.env` (каркас: меню из пяти разделов-заглушек, строка «В списке N тайтлов · последняя проверка…» обновляется сама раз в минуту). Карточка тайтла (тикет 02 части 5.2): `http://localhost:8080/titles/1` (номера идут по порядку добавления; тайтлы пока добавляет бот — «➕ Добавить»); галочка сезона, «Отметить все вышедшие», «Посмотрел» (фильм), «Удалить» → «Да, удалить» (переход на `/list`, там пока заглушка). Поиск (тикет 03 части 5.2): `http://localhost:8080/search` — тип, название от двух букв, подсказки через полсекунды, «Добавить» → карточка со строкой «Добавлено в список», у добавленного — «В списке». Список (тикет 05 части 5.2): `http://localhost:8080/list` — самые новые сверху, без просмотренного и брошенного; ряды ссылок «Все · Фильмы · Сериалы · Аниме», «Без архива · Хочу · … · Бросил · Весь список», «Сначала новые · По названию»; «Удалить несколько» → галочки → «Удалить выбранные (N)» → вопрос с названиями → «Да, удалить» → тот же Список со строкой «Удалено: …». «Бросил», «Вернуть в список», «Продолжения» (тикет 04 части 5.2): в карточке фильма «Хочу» — «Посмотрел», «Бросил», «Удалить»; у сериала и аниме вне архива — «Бросил», «Удалить»; у «Просмотрено» фильма — «Вернуть в список» и блок «Продолжения» («Ищу…» сразу после «Посмотрел», через минуту — строки с «Следить» или «В списке»); у брошенного — «Вернуть в список»; галочки у брошенного ставятся, статус не меняется; после «Вернуть в список» сообщений о том, что было в архиве, не приходит. Сезон по id записи (тикет 01 части 5.3): галочка сезона в карточке и кнопки «📺 Просмотренные сезоны» в боте отмечают тот же сезон; кнопки сезонов из сообщений, пришедших до обновления, отвечают «Эта кнопка устарела — откройте карточку заново»; при запуске применяется миграция 0011 (в журнале `0011`, копия базы в `data/backups/`). Оценки (тикет 02 части 5.3): `http://localhost:8080/titles/<номер просмотренного фильма>` — под статусом «Оценка» и список, выбрать «9+» — страница не перезагружается, оценка сохраняется (откройте карточку заново — «9+» на месте), «—» снимает; у фильма «Хочу» поля оценки нет; у сериала с двумя отмеченными сезонами — список «Оценка» у каждого отмеченного сезона (у неотмеченного нет) и у тайтла с первой строкой «По сезонам: …» и подписью «среднее по сезонам», пока своей оценки нет; выбрать число — своя оценка, «По сезонам» — снова среднее; снять галочку оценённого сезона — его списка нет, среднее без него; `http://localhost:8080/titles/99999999999999999999` — «Этого тайтла нет в списке»; в Telegram карточка тайтла показывает «Оценка: …» (ставить оценку в боте нельзя).

Тесты:
```powershell

```

## 8. Подводные камни (проверено на практике)

- **TMDb использует одно числовое пространство id для фильмов и сериалов.** Одно число может быть и `/movie/{id}`, и `/tv/{id}`. Поэтому нужно опрашивать оба эндпоинта; в БД ровно один тайтл на пару (источник, id). Старая запись неверного типа удаляется со всеми зависимыми строками до создания новой.
- **Внешние id в новой базе привязаны к источнику вида `tmdb_movie` / `tmdb_tv`**, а не к `tmdb`: уникальность по паре (источник, id) остаётся, и фильм с тем же числом, что у сериала, не конфликтует.
- **Даты фильма из `release_dates`:** кино — самая ранняя дата типа 3 среди всех регионов, цифровой релиз — типа 4 (тип 2 «ограниченный прокат» и 1 «премьера» не считаются). Регион владельца пока не учитывается.
- **Эпизод считается вышедшим только если `air_date` не пуст и не позже сегодня.** Эпизоды-заглушки анонсированного сезона имеют будущие даты и не должны превращать сезон в «вышедший».
- **Эндпоинт TMDb `/tv/{id}` не отдаёт список эпизодов**, только метаданные сезонов с `episode_count`. Даты эпизодов берутся пачками: `/tv/{id}?append_to_response=season/1,…` (до 20 сезонов за запрос, проверено на настоящем ответе; ответ содержит ключи `season/N`), сериал из 23 сезонов — 3 запроса.
- **TMDb `release_dates` — вложенный массив по регионам** с целочисленными типами (1 премьера, 2 ограниченный прокат, 3 прокат, 4 цифровой, 5 физический, 6 ТВ) и ключом `release_date`.
- **aiogram 3.x:** у `Message` нет `reply_text`, только `.answer()`; `InlineKeyboardMarkup(inline_keyboard=...)` требует список рядов `list[list[InlineKeyboardButton]]` (плоский список даёт `ValidationError`); проверка `event_from_user` доступна уже в middleware уровня `dp.update`; `start_polling` просит у Telegram только те типы апдейтов, на которые есть обработчики, поэтому inline-запросы боту больше не приходят.
- **SQLite:** метки времени хранятся как naive-UTC.
- **Shikimori:** один `franchise` объединяет кроссоверы, спешлы, OVA и фильмы, поэтому фильтр по названию даёт приближённый результат. Связи между тайтлами есть: `relationKind` (sequel, prequel, summary и т. д.) лежит не на `Anime`, а внутри `related { relationKind relationText anime { id kind } }`. Прежний агент искал поле на `Anime` и решил, что его нет.
- **Shikimori, цепочка сиквелов:** запрос `animes(franchise:)` не годится как основа: у части записей франшиза пуста (фильм «Созданный в Бездне: Тайна пробуждения. Часть 2» — `franchise: null`) и он тянет кроссоверы. Цепочку надёжно даёт обход по id: запрос `animes(ids:)` с `related { relationKind anime { id kind } }` и переход только по `prequel` / `sequel`. «Part N» ищется в оригинальном названии: у «Магическая битва: Смертельная миграция. Часть 2» русское название говорит «Часть 2», а оригинальное (`Kouhen`) — нет, и это сезон 4. У идущего аниме `episodes: 0` (число серий неизвестно), вышедшие считаются по `episodesAired`; `nextEpisodeAt` приходит со смещением (`+03:00`), в базе хранится UTC.
- **AniList, id по MAL-id:** запрос из нескольких `Media(idMal: …)` под разными именами целиком отвечает 404, если хоть один MAL-id AniList неизвестен. Нужна выборка `Page { media(idMal_in: […]) }`: неизвестные id просто отсутствуют.
- **AniList, расписание:** запись `Media` даёт `status` (`RELEASING`, `FINISHED`, `NOT_YET_RELEASED`), `episodes` (у идущей может быть null) и `nextAiringEpisode { episode airingAt }` (unix-время UTC). Номера серий у каждой записи свои, с 1, как у Shikimori. Выборка нескольких записей — `Page { media(id_in: […]) }`: неизвестный id просто отсутствует. AniList и Shikimori могут расходиться: на 24 октября 2026 у One Piece Shikimori ждёт серию 1181 25 октября, а AniList — 3 января 2027. Для расписания верим AniList, но если он промолчал, остаётся сохранённое.
- **Моменты вышедших серий аниме:** наш запрос к AniList не отдаёт список вышедших серий, поэтому их моменты мы не знаем. Дата, записанная впервые (из Shikimori или из момента проверки), больше не меняется; серия, найденная позже, чем она вышла, получает момент находки — отсюда небольшая задержка в «вышла серия», равная интервалу проверки (≤ 1 ч, когда серия близко).
- **Необъявленные имена:** `NameError` в редко выполняемых ветках находит `pyflakes` (`.venv\Scripts\python.exe -m pyflakes app tests`).
- **GitHub Desktop у владельца может смотреть копию проекта на диске C**, а бот живёт в `E:\LocalAI\Bionic\Telegram-bot` (там `.env`, `data`, `.venv`). Если после «Pull» файлы на E старые — в GitHub Desktop выбрать репозиторий на E (File → Add local repository). Проверка: `Select-String` по новому файлу в папке на E.
- **Скрипты вне проекта, читающие `.env`, не должны писать лог без `MaskingFormatter`** — иначе токен попадёт на экран.
- **`data/startup_failure.json` — запись о последнем сбое запуска** (отпечаток, с какого времени, когда ушёл отчёт; текста ошибки там нет). Пока она есть, тот же сбой не сообщается в Telegram чаще раза в сутки; удачный запуск её удаляет. Удалить руками можно — следующий сбой просто сообщится сразу.
- **`docker compose` подставляет переменные в значения `.env` и читает его для своих подстановок:** `$` портит значения (`Qwe$rty12345` → `Qwe`), `${` без `}` ломает все команды `docker compose`, даже `.\stop-bot.ps1`. Режим `format: raw` не годится (оставляет кавычки и комментарий в конце строки в значении, а подстановки для `docker-compose.yml` всё равно читает). Поэтому `.\start-bot.ps1` такой `.env` не пускает.

## 9. Отвергнутые подходы и заброшенное

- **Плоский список `release_dates` с типом-строкой `"Digital"` и ключом `iso_release_date`** (TMDb, Phase 6). Реальная форма — вложенные регионы, целочисленные типы и `release_date`. Не возвращаться.
- **Плоский список кнопок и параметр `inline_keys=` в aiogram.** Правильно `inline_keyboard=[[btn], [btn]]`.
- **Поиск с опечатками перебором вариантов** (Phase 20: удаления, перестановки, суффиксы). Результаты стабильно нерелевантны, нечёткий поиск API не совпадает с намерением пользователя. Нужен другой подход.
- **Кинопоиск / KinoPub** (Phase 12). Поддержка не выдаёт `CLIENT_ID` и `CLIENT_SECRET` без партнёрского договора, OAuth Device Flow без них недоступен. Исследование API v1 проведено, реализации нет. Событие «KinoPub» и «Русская озвучка» убраны из плана.
- **Правила READY_TO_WATCH** (Phase 13). Ни один источник не отдаёт сведений о русской озвучке, а владелец смотрит сериал по сериям, а не дожидается конца сезона.
- **Режим «пустой белый список = разработка».** Убран: пустой список не пускает никого, бот не стартует (шаг 1 куска 0).
- **PostgreSQL в проде.** Заменено на SQLite в режиме WAL (ADR 0005) — для одного владельца достаточно, бэкап — один файл.
- **Перенос текущей БД (11 тестовых тайтлов).** Новая база без переноса (кусок 1), старая лежит в `data/archive/`.
- **Неофициальный запрос PSN с `sha256Hash`** (хеш истекает без предупреждения; при HTTP 400 в лог пишется «требуется обновить sha256Hash»). Цены PlayStation пойдут через PlatPrices (ADR 0003).
- **Тестовые отчёты об ошибке через `html.escape` по умолчанию** — гипотеза, что апостроф (`&#x27;`) вызывает `HTTP 400`, не подтвердилась (причиной был `OWNER_CHAT_ID`); экранирование теперь `quote=False`.

## 10. Окружение и настройки

- ОС разработки: Windows 11 (PowerShell, bash через Git Bash). Python 3.12.10, venv `.venv/`. Docker 29.x. Сейчас приложение работает в Docker на ПК владельца, проверка — в браузере того же ПК (ADR 0006). Позже — NAS в Docker (кусок 7), доступ вне дома — Tailscale или Cloudflare Tunnel (решается при переезде).
- Файл `.env` (в git не попадает; значения не выводить). Читаются `Settings` в `app/config.py`:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен бота |
| `ALLOWED_TELEGRAM_USER_IDS` | да | Белый список (числа через запятую); пустой — бот не стартует |
| `OWNER_CHAT_ID` | нет | Число — id чата для событий и отчётов об ошибках (для личного чата равен вашему Telegram id); не число или пусто — первый из `ALLOWED_TELEGRAM_USER_IDS` |
| `TMDB_API_KEY` | да | Ключ TMDb |
| `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET` | для игр | Учётные данные Twitch/IGDB |
| `SHIKIMORI_BASE_URL`, `SHIKIMORI_USER_AGENT` | нет | Shikimori |
| `BOT_TIMEZONE` | нет | Часовой пояс владельца, например `Europe/Moscow` (по умолчанию `UTC` и предупреждение в журнале при запуске); в Docker им же выставляется `TZ` (время в журнале) |
| `WEB_PASSWORD` | для веба | Пароль входа в веб-приложение, не короче 8 символов (пробелы по краям не считаются); без него (или с коротким) вход закрыт страницей-подсказкой, бот работает как обычно. Смена пароля выбрасывает все входы. Ключ подписи сессий — `data/web_secret` (создаётся сам) |

| `PUID`, `PGID` | нет | Номер пользователя и группы процесса в контейнере (по умолчанию 1000); на NAS — владелец папки `data`; читает `app/container_start.py`, не `Settings` |

Опрос идёт раз в минуту (`TRACKER_BEAT_SECONDS` в `app/bot/main.py`) |

Знак `$` в значениях `.env` запрещён: `docker compose` подставляет переменные в значения (`Qwe$rty` станет `Qwe`), и `.\start-bot.ps1` такой `.env` не пускает.

## 11. Внешние сервисы

| Сервис | Статус | Назначение и особенности |
|---|---|---|
| TMDb | Работает | Фильмы и сериалы. Ключ `TMDB_API_KEY`. Старый лимит «40 запросов / 10 с» отключён в 2019 году, мягкие пределы около 40–50 запросов в секунду и 20 соединений с IP; на 429 — откат. Пакетного запроса нет, поэтому запросы идут по одному и разносятся во времени |
| AniList | Работает | Аниме: расписание, следующая серия. GraphQL `graphql.anilist.co`, ключ не нужен, около 90 запросов в минуту |
| Shikimori | Работает | Франшизы и сезоны аниме, русские названия. GraphQL `shikimori.io`, нужен `User-Agent`; связи сезонов — через `related { relationKind }` |
| IGDB | Клиент есть, не подключён | Игры (кусок 6): названия, даты, платформы. Client-ID + Bearer-токен Twitch (получается во время работы, в `.env` его нет) |
| Steam Store | Неофициальный | Клиент `app/providers/steam.py` есть, к боту не подключён (кусок 6). Поиск и страницы магазина, «coming soon». При блокировке — «недоступно», не ошибка |
| PlayStation Store | Не используется | Прежний клиент (поиск через RAWG, до этого неофициальный GraphQL с `sha256Hash`) удалён в тикете 12. Решение: цены через PlatPrices (ADR 0003, кусок 6); ключ PlatPrices запросить по e-mail |
| Telegram Bot API (aiogram 3.31) | Работает | Long polling |
| KinoPub / Кинопоиск | Не используется | См. раздел 9 |

## 12. База данных

SQLite в режиме WAL, файл `data/tracker.db`, SQLAlchemy 2, схема только через Alembic (`app/tracker/migrations/`, `alembic_tracker.ini`; миграции применяются при старте бота). Модели — `app/tracker/models.py` (тайтлы, внешние id, сезоны, серии, части сезонов, фильмы франшиз, снимки источников, события, очередь доставки, настройки). Старая база `bot.db` (11 тестовых тайтлов) и её копии лежат в `data/archive/`, бот их не читает; переносить из них ничего не нужно.
