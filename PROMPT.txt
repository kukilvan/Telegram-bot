# POLLING / SCHEDULER

Не проверяй каждый source одинаково часто.

Например условно:

релиз через несколько дней → чаще;

series near airtime → чаще;

KinoPub после ожидаемого выхода серии → чаще;

стабильное старое произведение → редко.

Но реальные интервалы выбери только после проверки API rate limits.

Не нарушай ограничения сервисов.

Используй retry с exponential backoff.

Добавь timeout.

Не допускай, чтобы временная ошибка API воспринималась как:

`произведение исчезло`.

вместо того чтобы молча выбрать одно значение.

# ЧАСОВЫЕ ПОЯСА

Все timestamps в базе храни правильно и последовательно, желательно UTC.

Для отображения используй пользовательский timezone.

Мой основной timezone:

`Asia/Jerusalem`.

Учитывай, что дата выхода серии в США вечером может приходиться уже на следующий день по местному времени.

# QUIET HOURS

Предусмотри настройку тихих часов.

Например:

23:30–08:00.

Можно выбрать:

отложить обычные уведомления до утра;

важные release events отправлять сразу.

Реализовать это можно позже, но архитектура notification layer должна позволять такую функцию.
