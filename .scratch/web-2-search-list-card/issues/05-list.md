## Что сделать

- **`list_titles(kind=None, statuses=None, order=…)`** (спека 2.1, 2.8) в `listing.py`: фильтр по типу и набору статусов; порядок «сначала недавно добавленные» (момент добавления от нового к старому, при равенстве номер от большего) и «по названию» (без учёта регистра, «ё» как «е»; цифры, затем латиница, затем кириллица; при равенстве — по номеру). Вызов без аргументов (бот) — как раньше: все тайтлы в порядке добавления. `TitleSummary` получает постер (остальное уже есть). Фильтры «по типу» и «по набору статусов» задаются перечислениями, строк в шаблонах нет (правило 6).
- **`app/web/title_list.py`** (спека 1.2, 5.1–5.4): `GET /list?kind=…&status=…&order=…&select=1`, `GET /list/selection?id=…`, `GET /list/confirm?id=…`, `POST /list/delete`. Заглушка «Список» в `SECTIONS` заменяется страницей.
  - Три ряда ссылок (`aria-current` у выбранной): тип — Все · Фильмы · Сериалы · Аниме (`kind`); статус — Без архива (по умолчанию) · Хочу · В процессе · Жду · Досмотреть · Просмотрено · Бросил · Весь список (`status`, `all` — весь); порядок — Сначала новые (по умолчанию) · По названию (`order=name`). Каждая ссылка — адрес Списка с изменённым одним параметром и прежними остальными; подписи статусов из `STATUS_LABELS`, адреса по значениям перечислений; неизвестное значение — как без него.
  - Строки (спека 5.1): макрос из 01 с постером `w92`, значком типа, названием, годом и статусом; вся строка — ссылка на карточку; над ними «Показано 12 тайтлов» (`cards.titles_word`); пусто без фильтров — «В списке пока ничего нет. Найдите тайтл в Поиске» со ссылкой; пусто с фильтром — «Под этот фильтр ничего не подходит» и «Сбросить фильтры». Постраничного вывода нет.
  - Режим выбора (спека 5.3): ссылка «Удалить несколько» (`select=1`); у каждой строки галочка (строка — уже не ссылка), внизу полоса «Удалить выбранные (N)» и «Отмена»; изменение галочки запрашивает `GET /list/selection` (число обновляется; без HTMX — не обновляется, кнопка доступна всегда); пока ничего не выбрано, кнопка недоступна.
  - Удаление (спека 5.4): «Удалить выбранные (N)» → `GET /list/confirm` → вопрос «Удалить 3 тайтла со всеми сезонами и событиями? «Дюна», «Магическая битва», «Пацаны»» (до 10 названий, дальше «и ещё N») с «Да, удалить» (форма `POST /list/delete`: id скрытыми полями, ровно те, о которых спросили, плюс текущие фильтры) и «Отмена». Тайтлы удаляются по одному (`delete_title`): уже удалённый пропускается, сбой одного не мешает остальным (запись в журнал). Итог — переход в Список с теми же фильтрами без режима выбора, со строкой «Удалено: «Дюна», «Пацаны»» (до 10, дальше «и ещё N»); не удалось — ещё «Не удалось удалить: «…». Попробуйте ещё раз»; всех уже не было — «Этих тайтлов уже нет в списке»; пустой запрос — Список без строки.
- **Переход из карточки** (02) в `/list` теперь попадает на настоящий Список; строка «Удалено: …» показывается.
- **Документация:** `docs/code-map.md`, `docs/tests-map.md`; `PROJECT_CONTEXT.md` — состояние (часть 5.2: все тикеты сделаны, дальше — код-ревью части) и раздел 4 (что проверять: Список); «Следующий шаг» меняет только «ОК».
