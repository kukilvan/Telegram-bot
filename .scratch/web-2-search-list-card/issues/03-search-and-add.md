# 03: Поиск и добавление (и KI-2)

**Сложность:** сложный (источники, очередь запросов, добавление в одной сессии записи, дубль аниме)
**Статус:** принят

Спека: `../spec.md`, разделы 1.5 (подсказки), 2.6, 2.7, 3, 6 (последний абзац), 7 (строки про поиск и добавление), 8 («Ядро»: подсказки, KI-2, TMDb; «Веб»: Поиск, добавление). Запись KI-2 в `KNOWN_ISSUES.md`. Термины — `CONTEXT.md`, стандарты — `docs/coding-standards.md` (правила 1, 6, 7, 9, 10).

**Blocked by:** 01 (модули веба, постеры, ответы страниц), 02 (карточка: добавление ведёт в неё)

## Что сделать

- **Источники** (спека 1.5, 2.7): в запрос `search_anime` (`app/providers/shikimori.py`) добавляется `poster { originalUrl }`; подсказки получают постер из поиска (TMDb — `poster_path` из ответа поиска). В клиенте TMDb (`app/providers/tmdb.py`) запросы поиска (`search_movie`, `search_tv`) не ждут ни паузы между запросами, ни предела в минуту, но учитываются в окне; на `429` поиск не повторяет запрос, а сразу сообщает об ошибке. Остальные запросы (добавление, опрос) — как сейчас. Бот ходит тем же поиском, поэтому тоже идёт вне очереди.
- **Известные id типа** (спека 2.6): новое действие объекта опроса рядом с `first_seasons`/`first_check`: у фильма и сериала — первичный id источника; у аниме — ещё `season_parts.shikimori_id` и `franchise_movies.shikimori_id` всех аниме-тайтлов. Итог — «id → номер тайтла». Типа не решает `if` (правила 6, 7).
- **`search(kind, query)`** (спека 2.1, 2.6): у каждой подсказки — постер и номер тайтла в списке (или пусто), найденный после ответа источника одним чтением базы по известным id. Бот поля номера и постера не использует; остальное поведение поиска не меняется.
- **`add_title(kind, external_id)` и KI-2** (спека 2.6): до запроса к источнику — id подсказки среди известных → открывается этот тайтл (`created=False`); после снимка, в той же сессии записи, где тайтл создаётся (правило 9), — известен ли тайтл по любому id снимка (у фильма и сериала по его id; у аниме по id первого сезона, всех частей и всех фильмов цепочки) → открывается он, второй копии нет. Снимок совпал с двумя тайтлами — открывается меньший номер, предупреждение в журнал. Запись KI-2 в `KNOWN_ISSUES.md` — «Исправлено (тест: …)». Подсказка, у которой в найденном нет сезона из базы, пометки «В списке» не получает, но «Добавить» не создаёт дубль.
- **`app/web/search.py`** (спека 1.2, 3.1–3.4): `GET /search` (с `?kind=…&q=…` — сразу с подсказками, без HTMX тоже), `GET /search/suggestions?kind=…&q=…` (фрагмент), `POST /titles` (`kind`, `external_id`). Переключатель Фильм · Сериал · Аниме (радиокнопки); выбран последний тип, по которому искали (в сессии), впервые «Фильм», `?kind=` важнее запомненного, неизвестный — как без него; под «Сериал» — строка про «Аниме». Подсказки: запрос через 500 мс после последней буквы (`delay:500ms`), при смене типа, по Enter; `hx-sync` с заменой устаревших; меньше двух знаков (после обрезки пробелов) — «Наберите хотя бы две буквы», ядро не вызывается; пусто — пусто; запрос длиннее 100 знаков обрезается; до 10 подсказок; строка по макросу из 01 и справа «Добавить» (форма `POST /titles`, кнопка «Добавляю…» и недоступна на время запроса) или «В списке» со ссылкой на карточку; «Ничего не нашлось по запросу «…». Попробуйте другое название или другой тип». Добавлено — переход в карточку со строкой «Добавлено в список» (у сериала и аниме с отмечаемыми сезонами плюс «Отметьте сезоны, которые уже посмотрели»); уже было — «Этот тайтл уже в списке».
- **Ошибки** (спека 3.4): источник не ответил, ответил ошибкой или «слишком часто» — «Не удалось связаться с TMDb. Попробуйте чуть позже» (у аниме — Shikimori; имя — `KINDS[тип].source_name`); `TitleNotFound` — «TMDb больше не знает этот тайтл. Поищите заново»; неизвестный тип — «Такого типа нет»; всё — на месте подсказок или кнопки, `200`, запись в журнал.
- **Заглушка «Поиск»** в `SECTIONS` заменяется настоящей страницей. Постер в `TitleCard` (из 02) и макрос из 01 уже есть — подсказки пользуются ими.
- **Документация:** `docs/code-map.md`, `docs/tests-map.md`; `PROJECT_CONTEXT.md` — состояние и раздел 4 (веб: Поиск); `KNOWN_ISSUES.md` — KI-2; «Следующий шаг» меняет только «ОК».
