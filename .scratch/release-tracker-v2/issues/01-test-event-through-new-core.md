# 01: Тестовое событие доходит до Telegram через новое ядро

**Сложность:** сложный (модель данных, миграции, очередь доставки)

**What to build:** владелец нажимает в боте «Тестовое событие», выбирает тип и получает сообщение. За этим стоит новое ядро трекера: отдельная новая база (Alembic с первой миграции, без `create_all`, режим WAL), фасад ядра с подменяемыми часами, источниками и отправителем, события и очередь доставки. Событие помечается доставленным только после успешной отправки и доставляется ровно один раз. Новые обработчики подключаются в тот же процесс бота рядом со старыми; старый опрос и старые уведомления выключаются. Пока доставка немедленная, окна доставки появятся в тикете 11. Спека: разделы «Архитектура», «Модель данных» (событие, очередь, настройки), «Доставка», «Переходный период».

**Blocked by:** None (can start immediately)

**Status:** done

- [x] Новая база создаётся миграцией Alembic в отдельном файле, режим WAL включён; старая база не трогается.
- [x] Метки времени выставляются при вставке, а не при импорте модулей.
- [x] Фасад ядра принимает часы, отправителя и источники извне; бот работает с ядром только через фасад.
- [x] «Тестовое событие» доступно только владельцу (белый список из куска 0) и показывает меню типов событий; новые типы в следующих тикетах регистрируются в этом меню без правки самой кнопки.
- [x] Сбой отправки оставляет событие в очереди, следующая попытка доставляет его; повторная доставка того же события невозможна (уникальный ключ дедупликации).
- [x] Старый опрос и его уведомления выключены, старые поиск и список продолжают работать.
- [x] Тесты на точке «ядро трекера»: поддельные часы, отправитель и SQLite в памяти; повтор после сбоя; ровно одна доставка.
