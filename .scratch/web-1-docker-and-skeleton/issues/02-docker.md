## Проверено в облаке

Облачная сессия 2026-10-27, `dockerd` запущен вручную, `.env` фиктивный (`BOT_TIMEZONE=Asia/Jerusalem`), папка `data` создана от `root` с файлом `data/logs/old.txt`. После проверки `data` и `.env` удалены.

- Docker Hub отвечал `429 Too Many Requests`; базовый образ взят из `mirror.gcr.io/library/python:3.12-slim` (`docker tag … python:3.12-slim`). Внутри сборки `pip` не доверял сертификату прокси песочницы, поэтому образ собран копией `Dockerfile` с двумя добавленными строками (`COPY --from=ca ca-bundle.crt …`, `ENV PIP_CERT=…`, `--build-context ca=/root/.ccr`); `docker compose up -d --no-build`. Сам `Dockerfile` проекта этих строк не содержит и на ПК владельца они не нужны.
- `docker compose ps`: `Up … (healthy)`, `127.0.0.1:8080->8080/tcp`; `docker port` — только `127.0.0.1`; запрос на другой адрес компьютера (`192.0.2.2:8080`) — отказ (код `000`).
- `ls -ln data`: `backups`, `logs`, `tracker.db*` и прежний `logs/old.txt` — владелец `1000 1000` (папка была от `root`); `/proc/1/status`: `Uid` и `Gid` — 1000; процесс 1 — `python -m app.main` (тот же PID, после `execv`).
- `data/logs/bot.log` создан; время в журнале `20:49:03` при `date` контейнера `18:49 UTC` — то есть по `Asia/Jerusalem`.
- `curl http://127.0.0.1:8080/health` → `200 {"status":"ok"}`; бот без сети пишет `бот: нет связи с Telegram, повтор через 30 с`, веб и `healthy` не страдают.
- `docker compose down` — 1,5 с; `docker compose stop` — 1,3 с, код выхода 0, в журнале «остановлено».
- `PUID=abc` → «PUID и PGID должны быть числами (…)», код 1; неизвестный пояс → предупреждение и UTC.
- Не проверено: Docker Desktop на Windows (права папки там не меняются, запись разрешена всем), автозапуск после перезагрузки ПК — это проверит владелец.
