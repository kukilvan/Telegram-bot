## Что сделать

- **Слова в `CONTEXT.md`** (спека 10) — до правки кода: «Оценка» — `score` (строка «в коде пока нет» уходит), шкала в третях балла, «среднее по сезонам»; у «Ленты» — блоки «Скоро» (`upcoming`), «Позже» (`later`), «Недавно» (`recent`).
- **`app/tracker/scores.py`** (спека 2.1) — чистый модуль без базы: `SCALE` (30 … 3, по убыванию), `label(value)` («9+», «9», «9−»; минус — `−`, U+2212), `average(values)` (точное среднее или «нет»), `rounded(average)` (ближайшее деление, ровно посередине — вверх), значение вне шкалы — `ValueError`. Подписи строятся из `m` (−1, 0, +1), литералов статусов нет (правило 6).
- **Миграция `0011`** (спека 2.2): колонки `titles.score` и `seasons.score` (целое, пусто — нет), у всех строк пустые; откат убирает обе; копию базы перед ней приложение делает само. Модели в `models.py`. Оценка живёт на записи сезона: `storage.relayout_records` её сохраняет; сезон, который Shikimori убрал, удаляется с оценкой — строка журнала о распавшемся сезоне называет и её.
- **Видимость и среднее** (спека 2.3): что можно ставить и что видно — по таблице (фильм — статус из `ARCHIVE_STATUSES`; сезон — стоит галочка; сезонный тайтл — хотя бы один отмеченный сезон или статус из архива; «сезонный ли» — из `KINDS` `is_seasonal`, не сравнением типа). Видимая оценка тайтла: своя, иначе среднее по видимым оценкам сезонов (`scores.rounded`), иначе нет. Смена статуса и галочки ничего не стирает. Удаление тайтла удаляет и оценки (каскад).
- **Методы фасада** (спека 2.4), все `async` в `asyncio.to_thread`, запись — одна сессия на проверку и изменение (правила 1, 9), `core` пере-экспортирует новые имена:
  - `set_title_score(title_id, score)` — значение шкалы или `None` (снять; у сериала и аниме — вернуть среднее); нет тайтла — `UnknownTitle`; ставить значение, когда оценку не видно, — `CannotScore`; снять можно всегда; возвращает «изменилось ли».
  - `set_season_score(title_id, season_id, score)` — по id записи сезона; сезона нет у этого тайтла (в том числе id чужого сезона) — `UnknownSeason`; галочки нет, а ставится значение — `CannotScore`.
  - `set_season_watched(title_id, season_id, watched)`, `toggle_season(title_id, season_id)` — **сезон по id записи**, не по номеру (KI-27); остальное как было (сезона нет у тайтла или в нём ничего не вышло — `UnknownSeason`).
  - `watchable_seasons(title_id)` — `WatchableSeason` получает `id` записи сезона.
  - `title_card(title_id)` (данные карточки, спека 2.5) — `TitleCard.score` (`ScoreView`: `own`, `average`, `shown`, `by_seasons`; `None`, когда оценку не видно), `SeasonRow` получает `id` и `score` (у сезона без галочки — нет). Оценки сезонов читаются в той же сессии, что карточка, без запроса на каждый сезон.
- **Общее.** `CannotScore` в `errors.py` («оценку ставят только просмотренному»); `WatchedResult` → общее `ChangeResult` (`changed: bool`, комментарий «False: нажатие ничего не изменило») у «Посмотрел», «Бросил», «Вернуть в список», «Отметить все вышедшие» и новых методов — обработчики бота и веба правятся этим же тикетом; один помощник «найти тайтл или `UnknownTitle`» в `statuses.py` вместо шести повторов (пожелание ревью 5.2). Если `statuses.py` с оценками выходит за 400 строк — оценки в свой модуль ядра (правило 7).
- **Вызывающие: сезон по id** (спека 4.3, раздел 6):
  - Веб: `POST /titles/{id}/seasons/{season_id}` (`watched=1` или без него) — `season_id` из `SeasonRow.id`; `UnknownSeason` — «Этого сезона больше нет — карточка обновлена»; карточка, открытая до перенумерации аниме, отмечает тот же сезон. Поиск (`search.py` берёт `watchable_seasons`) учитывает `id`.
  - Бот: `callback_data` кнопок сезонов — новая приставка с id записи (предложение: `tsid:<тайтл>:<id сезона>`, `tsid:<тайтл>:done`); старая `tsea:` отвечает «Эта кнопка устарела — откройте карточку заново» и ничего не меняет. Тест правила 3 (`tests/test_tracker_owner_filter.py`) получает новую приставку.
- **`KNOWN_ISSUES.md`:** KI-27 — «Исправлено (тест: …)».
- **Документация:** `docs/coding-standards.md` (правило 7 — модуль `scores`, строка `statuses` «…и оценки»); `docs/code-map.md`, `docs/tests-map.md`; `PROJECT_CONTEXT.md` — состояние (часть 5.3: тикет 01 сделан) и раздел 4 (что проверять: галочки сезонов, кнопки сезонов в боте); «Следующий шаг» меняет только «ОК».

## Критерии

Тесты — по разделу 9 спеки; без сети.

- [ ] Шкала: 28 значений от 3 до 30, подписи «1», «1+», «2−», …, «10−», «10»; «1−» и «10+» — `ValueError`; порядок 9− < 9 < 9+ < 10− < 10; среднее и округление («9» и «8+» → «9−», «9» и «9+» → «9+», одна оценка — она сама, нет оценок — нет).
- [ ] Оценки: поставить, заменить, снять у фильма, сезона и тайтла; `CannotScore` у «Хочу» фильма, у сезона без галочки, у сериала без отметок вне архива; снять — можно всегда; среднее по видимым оценкам, своя поверх среднего, «вернуть среднее»; после «Вернуть в список» оценка фильма не видна и снова видна после «Посмотрел»; снятая галочка прячет оценку сезона и убирает её из среднего (поставили снова — вернулась); чужой `season_id` — `UnknownSeason`; удаление тайтла удаляет оценки; данные карточки (`ScoreView`, `SeasonRow.score`) по таблице 2.3.
- [ ] KI-27: аниме, сезон перенумерован (`relayout_records`) — галочка и оценка по старому id попадают в тот же сезон; распавшийся сезон — `UnknownSeason`; запись KI-27 — «Исправлено».
- [ ] Миграция `0011`: с нуля, на готовой базе после `0010`, откат; правило 6: подписи шкалы не литералами статусов.
- [ ] Веб: галочка по id записи (`UnknownSeason`, `UnknownTitle`, `303` без HTMX); бот: кнопки `tsid:` меняют отметку по id, старая `tsea:` — подсказка «устарела» без изменений; `ChangeResult` в обработчиках бота и веба.
- [ ] Новые модули не длиннее 400 строк (правило 7); `scores` — без базы.
- [ ] `pyflakes app tests` чистый; набор тестов зелёный.
- [ ] Пошаговая проверка для владельца (формат — `CLAUDE.md`): `http://localhost:8080/titles/<номер сериала>` — галочка сезона ставится и снимается без перезагрузки страницы, статус меняется сам; «Отметить все вышедшие» работает; в Telegram: карточка сериала → «Просмотренные сезоны» → кнопки сезонов отмечают то же, что в вебе; бот при запуске применяет миграцию (в журнале `0011`), красного текста нет, копия базы появилась в `data/backups/`.
